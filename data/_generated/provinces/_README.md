# 省级单位「自身」轮廓缓存 —— `{省adcode}.geo.json`
#
# 用途：首页 / 省级页在**省这一级**画"省的面"时用它（省标签 → 省的轮廓）。
#       读不到就退回"用该省各市的轮廓拼"（那条会把省**内部**的市界也画出来）。
#       读取入口：`web/app/common/data/data.ts` 的 `loadProvinceOwnOutline`
#                 → `loadProvinceFaces`（入口 `loadBoundsForLevel('province')`）。
#
# 生成：`python pipeline/run.py outline`（构建期跑一次，**运行时零请求**）
#       源码：`pipeline/step9_province_outline.py` + `pipeline/amap.py`
#
# ⚠️ 为什么不在这儿拿腾讯的：
#    腾讯 District **没有"省自身"轮廓的接口** —— `getchildren?id=<省>` 返回的是它下辖的
#    **市**；`search` 任何参数都不带 polygon；`/district/v1/boundary` 不存在；
#    `id=100000`（中国）返回 0 个节点；`max_offset` 改了点数一字不变。
#    而"各市拼省"做不出纯外轮廓：腾讯给每个市的是**各自独立抽稀**的边界，
#    相邻市共享边界的顶点不重合（`districts/110000.geo.json` 里北京 16 个区每个只有 4~28 个点）。
#
# 🚨 合规（这一条决定"能换成谁"）：
#    边界只能来自**持牌图商 / 官方平台**（腾讯 / 高德 / 百度 / 天地图）——它们的数据过了审图。
#    **绝对禁止**任何第三方 GeoJSON（Natural Earth / GADM / geoBoundaries / 各种开源数据集），
#    因为台湾省、藏南地区、南海诸岛、阿克赛钦的表达常出错，违反《地图管理条例》。
#    本条与 `districts/_README.md` 的红线同源，见 plans/10 第九节。
#
# ★ 为什么是高德而不是天地图：高德返回 **GCJ-02**，与腾讯底图 / 腾讯 District /
#   我们的 POI **同系** ⇒ **零坐标转换**。天地图是 CGCS2000（≈WGS-84），要转，
#   偏移 50~500m —— 在省这一档（z≈4~6）是亚像素、看不出来，但**绝不能**用在区/点位档。
#   ★ 也正因为如此，**只有"省"这一级换源**：市/区/点位继续用腾讯。
#
# 文件结构（与 districts/*.geo.json 完全一致，前端零改动）：
#   {
#     "adcode": "510000",
#     "name": "四川省",
#     "source": "amap",                     ← ★ 溯源：这一份不是腾讯的
#     "level": "province",
#     "polygons": { "510000": [ [lng,lat,lng,lat,…], … ] },   ← 平坦串，步长 2
#     "fetchedAt": "2026-09-30"
#   }
#
# 预期文件：**全部 34 个省级单位**（含中国台湾 710000 / 中国香港 810000 / 中国澳门 820000）。
#   ★★ 2026-09-30 晚改：第一版只抓"有收录城市的省"，结果图上一半的省没有面
#      （用户报：「轮廓数据好像没抓全，只有部分省的部分区是全的」）。
#      未收录的省走**「待收录」灰虚线**样式（`districtStyles` 的 pending 档）——
#      那本来就是 10 文档 §6.3 的视觉语言；顺带满足 §9.2「全国图必须包含 34 个省级单位」。
# 已知缺口：高德官方文档写明「暂时不支持中国台湾省的详细区划查询」⇒ 710000 抓不到，
#          脚本会跳过（**不写空文件**），该省继续走兜底路径。
