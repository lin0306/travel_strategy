# 05 · 页面结构与 UI 设计

> 视觉基调：明亮、清爽、有旅行感；信息密度中等偏上，图片是主角。
> 所有界面提示用 Tooltip 组件，禁止 HTML `title` 属性；禁止硬编码 size / shape，统一走 design token。

## 一、页面结构

### 1.0 布局模型：地图即画布（Map as Canvas）

> **这是全站唯一的布局模型，两端共用。** 早期方案里的「地图占左 60% + 列表占右 40%」分栏已废弃。

```
┌───────────────────── 屏幕视口（100% × 100%）─────────────────────┐
│                                                                  │
│                  底 层：全 屏 地 图 画 布                         │
│                （z=0，铺满，不参与文档流）                         │
│                                                                  │
│   ┌─ 浮层 A ─┐   ┌──── 浮层 B ────┐      ┌─ 浮层 C ─┐            │
│   │ 白底      │   │ 白底 + 投影     │      │          │           │
│   │ 圆角 + 投影│   │                │      │          │           │
│   └──────────┘   └────────────────┘      └──────────┘            │
│                                                                  │
│        ┌──── 浮层 D（底部条）────┐                                │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

**四条硬规则**（违反任何一条就退回分栏老路）：

1. **地图是页面本身，不是页面里的一个组件。** 屏幕容器 `position:relative`，地图层 `position:absolute; inset:0`，永远 100% × 100%。
2. **所有 UI 都是浮层**：统一 `position:absolute` + 白底 + 圆角 + 投影。没有「并排」，只有「悬浮」；没有「区块」，只有「浮层」。
3. **浮层没盖到的地方，永远露着地图。** 这意味着面板必须**定宽 / 定档位**（如左面板 348px、右卡片 326px、Sheet 三档），而不是 `flex:1` 去挤占地图。
4. **关掉任何浮层，地图不变形。** 面板是「盖」在地图上，不是「挤」地图。所以：详情面板打开时不重算地图尺寸，只让视野 `panTo` 到目标点（`map.panTo()`）。

**为什么改**：分栏模型里「地图」和「内容」在争同一块面积的解释权，结果两边都做不好 —— 地图永远只是一条窄带，而"空间关系"恰恰是地图存在的唯一理由。改成浮层后，地图拿到 100% 面积，UI 变成可以随时收起、随手拖动的注脚。

- **每个省一个计数徽标（CountBadge）**："四川 46"。数字是该省**已收录**景点数，来自构建期 `district-tree.json`，**零运行时调用**。
- **未收录的省显示"待收录"**（灰色 + 虚线描边 + 破折号 `—`），**不是 0** —— 0 表示"收录了但确实没有"，与"还没做"是两回事（见 [10](./10-map-drilldown.md) 第六节）。
- **省级填充色 = 收录密度**（四级：未收录 / 1–19 / 20–49 / 50+），让"哪里有内容"一眼可见。
- **点击省 → 下钻到 P2 省级页**。下钻是客户端路由切换，**地图实例复用、不重载**（见 [10](./10-map-drilldown.md) 第五节）。
- 左侧面板与地图双向联动（hover 行 → 省高亮；点省 → 行选中并下钻）。

> 与早期"城市选择网格"的区别：**入口从"选城市"升级为"看全国"**。用户先建立"哪里值得去、内容有多少"的整体印象，再逐级下钻，而不是一上来就在 10 个城市里二选一。

**四处关键取舍**：

| 取舍 | 说明 |
|------|------|
| **右侧卡片替代地图气泡（InfoWindow）** | 气泡在密集点位下互相遮挡，且塞不下「开放时间/建议时长/地址」这些字段。改成悬浮卡后字段能放全，也不再遮地图 |
| **筛选与列表同处一块浮层** | 分类 chips + **细类图例** + 搜索 + 排序 + 列表全在左面板内，不需要「点筛选 → 弹面板 → 再关」的往返 |
| **点位颜色由细类决定** | 大类筛选 chip 用自己的主色，**marker 颜色由 `subtype` 决定**（12 色，见 [02](./02-data-model.md) SUBTYPE_META）。两者分开，避免"筛景点"和"看颜色"互相干扰 |
| **选中反馈优先做在地图上** | 地图永远是主角：选中先让 marker 放大外发光 + 视野 `panTo`，其次才是列表高亮 |

> 卡片里展示**适游群体标签**（`audience` → 「情侣 · 朋友」样式的小 chip）与 **♿ 无障碍友好**标识（`accessible=true` 才出现，默认不显示）。
> 移动端（S 档）是同一模型，只是浮层形态换成「顶部胶囊 + 底部 Sheet 三档吸附」。骨架见 [08-mobile-adaptation.md](./08-mobile-adaptation.md) 第 2.2 节。

### P4 POI 详情（双轨：城市页抽屉 + 独立详情页）

**SEO 带来一个连锁变更**：抽屉是纯前端交互态，搜索引擎抓不到、也无法单独分享。所以详情需要两条入口，但**内容只写一份**。

```
                     components/poi/PoiDetail.tsx   ← ★ 唯一内容实现
                     （封面 Gallery / 元信息 / 正文 / 亮点 / 来源）
                                  │
              ┌───────────────────┴───────────────────┐
              ▼                                       ▼
  PoiPreviewCard（城市页内交互用）          routes/city-poi.tsx（独立页）
  ├─ 右侧 326px 悬浮卡（预览态）             ├─ 面包屑浮层：返回城市页 / 成都 / 宽窄巷子
  ├─ 打开时不改 URL（保持地图上下文）        ├─ 左侧 620px 悬浮内容面板（内部滚动）
  ├─ 底部「复制链接」→ 详情页 URL           ├─ 同款 PoiDetail
  └─ Esc / 点浮层外关闭                     └─ ★ 被预渲染成静态 HTML，供搜索引擎收录
```

- **城市页内点 marker / 卡片** → 右侧浮出预览卡，URL 不变（连续浏览多个 POI 时不打断地图上下文）
- **预览卡里点「查看详情」** → 跳 `/city/:cityId/poi/:poiId`
- **从搜索引擎或他人分享进入** → 直接落到独立详情页，内容完整可见

> 这个设计的取舍：抽屉状态不可分享，但换来了「同一份内容两种容器」的清晰边界 —— 避免同一 URL 出现两种渲染形态（那会让 SEO 与状态同步都变复杂）。想分享单个 POI，用预览卡里的复制链接按钮即可。

**独立详情页也是地图即画布**：地图铺满并定位到该 POI（保留周边点位提供空间参照），内容浮在左侧，右下角另有一张「位置与到达」浮卡。

```

│ ┌─ 顶栏浮层 ──────────────────────────────────────────────────┐ │
│ │ [← 返回城市页]  成都 / 宽窄巷子      [分享] [矢量│影像] ◱  │ │
│ └─────────────────────────────────────────────────────────────┘ │
│ ┌─ 左内容面板 620px ────────┐                    ◎(目标·光晕)    │
│ │ ┌───────────────────────┐ │         ●                        │
│ │ │      封面大图         │ │                                  │
│ │ ├────┬────┬────┬────┤    │ │              ●        ●          │
│ │ │缩略│缩略│缩略│缩略│    │ │                                  │
│ │ └────┴────┴────┴────┘    │ │        ●           ┌─位置卡─┐   │

│ │ │开放时间¹│ 门票 ¹ │       │ │                                │

│ │ │建议时长 │最佳时段 │       │ │                                │
```

内容顺序（**「交通」不再单独成节** —— 它与右侧「位置与到达」浮卡的信息重复，统一由浮卡承载）：

```
封面大图 + 缩略图带（点击放大 lightbox，每张带可点署名）
名称 · 分类 badge · 一句话摘要
实用信息栅格 2×2：开放时间 / 门票 / 建议时长 / 最佳时段   ← 关键字段带来源角标 ¹
亮点 highlights
数据来源 sources（编号角标 → 可点链接 + 抓取日期，含图片版权声明）
```

> 右侧「位置与到达」浮卡承载：行政区 / 地址 / 最近地铁 + 【在地图上定位】。这样能省下约 90px 的纵向内容高度，让 620px 面板在 820px 视口内**一屏放完不裁切**（原型已按此验收）。

### P5 行程规划页 `/city/:cityId/plan` — 本轮新增

**产品主张**：用户自己定住宿、自己挑点位、自己排顺序，**系统只算时间**。所以这一页的主角是**时间轴**，地图是配角（提供空间校验）。

```
┌ 全屏地图（当天点位 + 连线 + 序号标记 + 住宿点图标）───────────────┐
│ ┌─ 顶栏浮层 ──────────────────────────────────────────────────┐ │
│ │ [← 成都]  我的行程   [第1天│第2天│第3天]      [导出] [分享]  │ │
│ └─────────────────────────────────────────────────────────────┘ │
│ ┌─ 行程面板 420px ──────────┐                  ▲(住宿点)        │
│ │ 住宿 春熙路某酒店  [更换]  │                   │              │
│ │ 09:00 出发                │       ①───────────┘              │
│ │ ═════════════════════════ │       │                          │
│ │ ⬤ 09:18  宽窄巷子          │       │   ②                      │
│ │ │  停留 90 分 · [改]        │       │  ╱                       │
│ │ │  🚗 18分 · 4.2km  [换]   │       ③╱                        │
│ │ ⬤ 10:48  人民公园          │                                  │
│ │ │  停留 60 分 · [改]        │      ④                           │
│ │ │  🚶 12分 · 0.9km  [换]   │                                  │

│ │ │  …                       │                                  │
│ │ ═════════════════════════ │                                  │

│ └────────────────────────────┘                                  │
│ ┌─ 底部图例条 ────────────────────────────────────────────────┐ │

└──────────────────────────────────────────────────────────────────┘
```

**四处关键取舍**：

| 取舍 | 说明 |
|------|------|
| **面板比城市页更宽（420px vs 348px）** | 时间轴每行要放「时间 + 名称 + 停留 + 方式 + 时长 + 距离」，348px 会挤成三行。新增 token `--panel-itinerary: 420px`，**不允许硬编码** |
| **顺序由用户定，系统只给事实与建议** | 不做自动排序。过载提示一律用「陈述 + 建议」措辞（「行程排到 22:47，可能过晚 · 建议减少 1 个点位」），**不用祈使句** |
| **连线在静态矩阵下是直连** | 预计算矩阵只存距离与时长、不存路径点（否则体积暴涨）。所以静态命中的段是**直连**，必须在段上标注「直线示意」；只有运行时真调了路线规划才画真实折线（见 03 文档 5.1） |
| **住宿点是隐私** | 住宿点只存 `localStorage`，**不进 URL**；分享时默认脱敏为「住宿点」不带名称 |

> 移动端是同一模型：保留「地图铺满 + 连线」，行程面板换成**底部 Sheet 三档吸附**（peek 看首段 / half 看前 3–4 项 / full 完整时间轴 + 操作）。完整形态见 [08](./08-mobile-adaptation.md) 第 3·B 节。
> 行程规划器的完整产品逻辑（数据模型、通勤三级来源、时间链推导、降级）见 [09-itinerary-planner.md](./09-itinerary-planner.md)。

## 三、交互流程

```
进入 /（全国页）
  → 预渲染 HTML 已就位（各省景点数来自 district-tree.json）
  → hydrate → 地图铺满 → 画 34 个省级面 + CountBadge → fitBounds(全国)
  → 未收录省渲染"待收录"灰显（点击弹引导，不下钻）
  → 点击某省级面 / 面板行 → 客户端路由切到 /province/:adcode
      地图实例**复用不重载**，只换图层（省面 → 市面）与视野（fitBounds 到该省）

进入 /province/:adcode（省级页）
  → 该省市级面 + 各市 CountBadge（已收录市显示景点数，未收录显示"待收录"）
  → 点击已收录市 → /city/:cityId（进入下面「进入城市页」流程）
  → 点击未收录市 → PendingCard「内容整理中，先看看省会 / 邻近已收录市」
  → 面包屑「全国」可回上级

进入城市页
  → 预渲染 HTML 已就位（文案立即可见，无骨架屏）
  → hydrate → 地图铺满视口 → 初始化 → fitBounds(allPois, padding)   ← padding 来自浮层实测
  → 浮层就位：顶栏 / 左面板 / 控件组 / 底部图例条
  → 默认「全部」大类 + 分端默认底图（移动矢量 / 桌面影像，可被 zoom 自动降级，见 03 文档 2.3）

点击分类 Tab / 细类图例
  → 过滤 visiblePois → 图层 clear + add（marker 颜色按 subtype 渲染）
  → autoFit 为 true 时重新 fitBounds

hover 列表卡片 → 对应 marker 高亮（不移动地图）
点击 列表卡片 / marker
  → 双向选中 → panTo 定位 → 右侧浮出 PoiPreviewCard（URL 不变）
  → 再点「查看详情」→ 跳 PoiDetail 独立页
关闭预览卡 → 保留选中态，便于继续看下一个；地图不重算尺寸

切换 矢量⇄影像 → map.setBaseMap({type, features}) → 同步 localStorage
放大到 zoom ≥ 15.5 且仍看影像 → 自动降级为矢量 + 一次性说明（可"以后不要自动切"）
key 缺失 / SDK 失败 → 浮出引导卡片（含"使用我自己的 Key"入口），左面板列表 + 详情**照常完全可用**

搜索输入（防抖 300ms）→ 名字/tags/描述匹配 → 空结果给引导文案
手动拖动地图 → autoFit=false → 显示"回到全览"按钮
移动端：地图铺满视口，**单指直接拖地图**（app-shell 下页面本身不滚，无手势冲突）
        → 点 marker 不弹气泡：Sheet 升到 half 档 + 卡片高亮并滚入视野
        → Sheet 三档吸附（peek / half / full），到顶下拉可降档（见 08 文档第三节）

── 行程规划页（P5，见 09 文档）────────────────────────────────
进入 /city/:cityId/plan
  → 空壳已预渲染（含说明与引导）；行程数据从 localStorage 读取填充
  → 无行程 → 引导「先选一个住宿点」（StayPicker 打开）
  → 有行程 → 渲染时间轴 + 地图连线 + 视野框住当天点位

设定住宿点（StayPicker）
  → 三路：从 POI 里选 / 搜索地址（走地理编码，1 次调用）/ 地图上点选（拖拽确认）
  → 支持多住宿段：加第二个酒店时要求指定「从第几天到第几天」

添加点位 → 复用城市页的 PoiPickerSheet（**不重新实现一套选择器**）
  → 选中后追加到当天末尾，时间链实时重算（矩阵命中 → 同步纯函数，零延迟）

拖拽排序
  → 同一天内：直接生效，连线与时间链实时重算（每帧 ≤ 16ms）
  → 拖到另一天：若目标天的 stayId 不同 → 二次确认「第 3 天住的是另一个酒店，仍要移过去吗？」
  → 移动端：**长按 300ms 激活拖拽态**，避免与 Sheet 下拉手势打架

修改停留时长 / 切换某段交通方式
  → 时长：时间链重算
  → 方式：走三级解析（矩阵 → 缓存 → 实时）。**公交 / 地铁**与住宿点相关会触发实时调用，显示 loading 态
  → 方式切换（六种：驾车 / 打车 / 公交 / 地铁 / 骑行 / 步行）**各给多条备选路线**（驾车走 `get_mp=1` 拿最多 3 条 + `get_speed=1` 显示路况，点开某段才懒加载）
  → 「不适用」的方式灰掉并给出可用方式提示（如「步行不适用 12.3 km · 建议驾车 22 分」）

时间链完成 → 过载检查（结束晚于 22:00 / 在途占比过高 / 单段超 60 分）
  → 以「陈述事实 + 建议」措辞提示，**不用祈使句**（顺序的决定权在用户）

导出 / 分享 → 导出 JSON 文件 / 生成分享链接（LZ-string 压进 URL hash，纯前端可解）
  → ⚠️ 分享时住宿点**默认脱敏**（只显示「住宿点」不带名称）
```

> ⚠️ **地图挂了不影响行程**：时间链读的是预计算矩阵（纯数据），**不依赖地图实例**。实现时必须守住这个边界 —— 不要把矩阵读取写成需要 `map` 参数的代码。城市页与行程页共用 `MapFallback` 降级卡片。

## 三·B、SEO 实现清单

预渲染解决了"HTML 里有内容"，但要在搜索结果里**显示得好**，还需要下面这些：

| # | 项 | 做法 |
|---|----|------|
| S1 | 每页 `<title>` / `description` | 用 React Router 7 的 `meta()` 导出，从 loader 数据推导（见 02 文档第六节）。**全国页**（`城市旅游攻略 · 景点美食地图`）、**省级页**（`{省}旅游攻略 · {N} 个景点收录`）、**城市页**、**详情页**各自一套 |
| S2 | `canonical` | 每页指向自己的规范 URL，避免参数页重复收录 |
| S3 | Open Graph / Twitter Card | `og:title` / `og:image`（取 POI 封面）/ `og:type=article`，社交分享出大图卡片 |
| S4 | **JSON-LD 结构化数据** | 城市页 `TouristDestination`、详情页 `TouristAttraction`（含 `geo` 坐标、`address`、`image`），百度/Bing 可出富摘要；**省级页**可用 `AdministrativeArea` |
| S5 | `sitemap.xml` | 构建后脚本扫描 `dist/**/index.html` 生成，或由 `prerender()` 的路由列表直接产出。**必须涵盖 34 个省级页 + 城市页 + 全部 POI 页** |
| S6 | `robots.txt` | 放 `public/`，声明 sitemap 地址 |
| S7 | 语义化标签 | 一个 `<h1>`、层级正确的 `<h2>/<h3>`、`<nav>/<main>/<article>` |
| S8 | 图片 `alt` | Schema 已强制中文 `alt`，直接透出 |
| S9 | 内链 | 详情页加「同城同类推荐」，城市页内所有 POI 卡片都是 `<Link>`；**下钻链路本身就是天然内链**（全国 → 省 → 市层层可达） |
| S10 | 404 | Netlify 下 `_redirects` 兜底到首页，或提供独立 404 页 |

> ⚠️ **验收必须用 `npm run build && npm run preview`**。`npm run dev` 是 CSR，`查看源代码` 里只有空壳 —— 拿它验 SEO 会得出错误结论。最快自检：
> ```bash
> npm run build && grep -o '<title>[^<]*</title>' dist/city/chengdu/index.html
> grep -c '武侯祠' dist/city/chengdu/poi/wuhou-shrine/index.html
> ```

### 响应式断点（**移动优先**）

默认样式写的就是移动端，媒体查询只做**向上增强**。禁止先写桌面再 `max-md:` 覆盖。

| 档 | 宽度 | 浮层布局要点（底层永远是全屏地图） |
|----|------|---------|
| **S（默认）** | **< 640px** | 地图铺满 `100svh`；**顶部一行悬浮胶囊**（城市 / 搜索 / 底图 / 定位）；内容全部收进**底部 Sheet 三档吸附**（peek 28svh / half 56svh / full 88svh）；图例与版权缩为 Sheet 上沿外的一条小字 |
| M | 640–1023px | 地图仍铺满；左面板放宽到 `320px` 悬浮；Sheet 退化为定高悬浮面板（不再可拖）；右预览卡改由 Sheet 内高亮卡片承载 |
| L | 1024–1439px | 地图铺满；左面板 `348px` + 右预览卡 `300px` 同时悬浮；底部图例条完整展开 |
| XL | ≥ 1440px | 地图铺满；左面板 `348px` + 右预览卡 `326px`；内容面板（详情页）`620px`；内边距统一 `16px`，浮层间距 `12px` |

> **三档以上不再改变布局模型，只改浮层尺寸。** 地图在任何档位都占 100% —— 这是 1.0 节规则的直接推论。
> **下钻页（P1 / P2）与行程规划页（P5）沿用同一模型**，只是把 `--panel-left` 的内容换成"省 / 市列表"或"行程时间轴"（后者用更宽的 `--panel-itinerary`），移动端把面板换成 Sheet。
> 详细骨架图、Sheet 档位、手势矩阵、安全区与触控规范 → [08-mobile-adaptation.md](./08-mobile-adaptation.md)

> ⚠️ `--panel-*` 这组值**不只是样式**：03 文档 4.1 节的「浮层实测 → 地图 `avoid` 参数」直接读它们。**改了面板宽度，地图的可视区会自动跟着变** —— 这也是为什么这些宽度必须走 token 而不能硬编码。

### 无障碍与细节
- 图片必须有 `alt`；图标按钮必须有 `aria-label`。
- 键盘：Tab 可遍历卡片，Enter 打开详情，Esc 关闭当前浮层（预览卡 / Sheet）。
- 空态：无结果 / 地图加载失败（提示 + 重试 + 静态降级列表）/ **未收录的省或市（"待收录"灰显 + 引导卡，不是空白）**。
- **适游群体标签**必须能被读屏读出（不是纯装饰图标）；**♿ 无障碍友好**用图标 + `aria-label="无障碍友好"`，且**只在 `accessible=true` 时渲染**（默认不显示，避免用"没有标识"暗示"不友好"）。
- 骨架屏：城市 JSON 加载、图片加载各一套；**下钻换层时保留上一层的面与徽标**，不做整屏骨架（避免闪烁）。

|------|------|------------------|
| LCP | ≤ 2.0s | **≤ 2.5s**（取百度/Google 硬标准；定 2.0s 会变成长期超标项） |
| INP | ≤ 200ms | ≤ 200ms（地图交互、Sheet 拖拽是主要风险） |
| CLS | ≤ 0.1 | **≤ 0.05**（Sheet 换档与图片无尺寸是主要偏移来源） |
| 预渲染 HTML | ≤ 60KB / 页 | 同（含文案 + meta + JSON-LD） |
| 首屏 JS | ≤ 200KB gzip | 同（**地图 SDK 单独异步 chunk，不阻塞首屏**） |
| 城市 JSON | ≤ 300KB gzip（实测约 30KB，实际不会触顶） | 同 |
| 图片 | 封面 1080w | **列表 400w / 详情 800w**；`srcset` + `sizes` 交给浏览器选；Hero 加 `fetchpriority="high"`，其余 lazy + 显式宽高 |
| 图片降级 | `ImageLazy` 三级：主图 → 下一张候选 → 风格化占位卡，**绝不留破图** | 同 |
| 地图可用 | `mapReady` ≤ 1.5s；**默认影像底图** | 同；**默认矢量底图**（影像瓦片体积 5–10 倍，见 03 文档 2.6） |
| 地图故障 | key 缺失 / SDK 失败时页面**仍完全可用**（列表 + 详情独立于地图） | 同 |
| **行程时间链重算** | **≤ 16ms（一帧内）** | 同；拖拽排序时每帧重算，矩阵命中路径必须是**同步纯函数**（见 09 文档 5.1） |
| **行程页运行时 API 调用** | **默认 0 次** | 同；通勤时长读预计算矩阵。仅「自定住宿点」与「公交 / 地铁」实时调，带缓存 + 配额账本 |
| **下钻换层** | ≤ 300ms（含边界缓存命中） | 地图实例复用，只清 / 加图层与 `fitBounds`；省级面首次加载走 `district-bounds/` 缓存（见 10 文档第五节） |
| **下钻运行时 API 调用** | **默认 0 次** | 计数读 `district-tree.json`；边界命中缓存。仅缓存未命中时才拉一次区划边界 |

> 📏 **移动端指标必须用真机 + 网络节流验收**（DevTools 的移动模拟不还原微信内核，也不还原跨境链路）。测试矩阵与待实测项见 [08-mobile-adaptation.md](./08-mobile-adaptation.md) 第 7.5 / 第九节。

```bash
npm run build

# 1. 首页（全国页）有正文与 title，且含省级计数
```
