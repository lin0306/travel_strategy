# 05 · 页面结构与 UI 设计

> 视觉基调：明亮、清爽、有旅行感；信息密度中等偏上，图片是主角。
> 所有界面提示用 Tooltip 组件，禁止 HTML `title` 属性；禁止硬编码 size / shape，统一走 design token。

## 一、页面结构

### 1.0 布局模型：地图即画布（Map as Canvas）

> **这是全站唯一的布局模型，两端共用。** 早期方案里的「地图占左 60% + 列表占右 40%」分栏已废弃。

```
┌───────────────────── 屏幕视口（100% × 100%）─────────────────────┐
│                                                                  │
│                  底 层：全 屏 地 图 画 布                         │
│                （z=0，铺满，不参与文档流）                         │
│                                                                  │
│   ┌─ 浮层 A ─┐   ┌──── 浮层 B ────┐      ┌─ 浮层 C ─┐            │
│   │ 白底      │   │ 白底 + 投影     │      │          │           │
│   │ 圆角 + 投影│   │                │      │          │           │
│   └──────────┘   └────────────────┘      └──────────┘            │
│                                                                  │
│        ┌──── 浮层 D（底部条）────┐                                │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

**四条硬规则**（违反任何一条就退回分栏老路）：

1. **地图是页面本身，不是页面里的一个组件。** 屏幕容器 `position:relative`，地图层 `position:absolute; inset:0`，永远 100% × 100%。
2. **所有 UI 都是浮层**：统一 `position:absolute` + 白底 + 圆角 + 投影。没有「并排」，只有「悬浮」；没有「区块」，只有「浮层」。
3. **浮层没盖到的地方，永远露着地图。** 这意味着面板必须**定宽 / 定档位**（如左面板 348px、右卡片 326px、Sheet 三档），而不是 `flex:1` 去挤占地图。
4. **关掉任何浮层，地图不变形。** 面板是「盖」在地图上，不是「挤」地图。所以：详情面板打开时不重算地图尺寸，只让视野 `panTo` 到目标点（`map.panTo()`）。

**为什么改**：分栏模型里「地图」和「内容」在争同一块面积的解释权，结果两边都做不好 —— 地图永远只是一条窄带，而"空间关系"恰恰是地图存在的唯一理由。改成浮层后，地图拿到 100% 面积，UI 变成可以随时收起、随手拖动的注脚。

- **每个省一个计数徽标（CountBadge）**："四川 46"。数字是该省**已收录**景点数，来自构建期 `district-tree.json`，**零运行时调用**。
- **未收录的省显示"待收录"**（灰色 + 虚线描边 + 破折号 `—`），**不是 0** —— 0 表示"收录了但确实没有"，与"还没做"是两回事（见 [10](./10-map-drilldown.md) 第六节）。
- **省级填充色 = 收录密度**（四级：未收录 / 1–19 / 20–49 / 50+），让"哪里有内容"一眼可见。
- **点击省 → 下钻到 P2 省级页**。下钻是客户端路由切换，**地图实例复用、不重载**（见 [10](./10-map-drilldown.md) 第五节）。
- 左侧面板与地图双向联动（hover 行 → 省高亮；点省 → 行选中并下钻）。

> 与早期"城市选择网格"的区别：**入口从"选城市"升级为"看全国"**。用户先建立"哪里值得去、内容有多少"的整体印象，再逐级下钻，而不是一上来就在 10 个城市里二选一。

**四处关键取舍**：

| 取舍 | 说明 |
|------|------|
| **右侧卡片替代地图气泡（InfoWindow）** | 气泡在密集点位下互相遮挡，且塞不下「开放时间/建议时长/地址」这些字段。改成悬浮卡后字段能放全，也不再遮地图 |
| **筛选与列表同处一块浮层** | 分类 chips + **细类图例** + 搜索 + 排序 + 列表全在左面板内，不需要「点筛选 → 弹面板 → 再关」的往返 |
| **点位颜色由细类决定** | 大类筛选 chip 用自己的主色，**marker 颜色由 `subtype` 决定**（12 色，见 [02](./02-data-model.md) SUBTYPE_META）。两者分开，避免"筛景点"和"看颜色"互相干扰 |
| **选中反馈优先做在地图上** | 地图永远是主角：选中先让 marker 放大外发光 + 视野 `panTo`，其次才是列表高亮 |

> 卡片里展示**适游群体标签**（`audience` → 「情侣 · 朋友」样式的小 chip）与 **♿ 无障碍友好**标识（`accessible=true` 才出现，默认不显示）。
> 移动端（S 档）是同一模型，只是浮层形态换成「顶部胶囊 + 底部 Sheet 三档吸附」。骨架见 [08-mobile-adaptation.md](./08-mobile-adaptation.md) 第 2.2 节。

### P4 POI 详情（双轨：城市页抽屉 + 独立详情页）

**SEO 带来一个连锁变更**：抽屉是纯前端交互态，搜索引擎抓不到、也无法单独分享。所以详情需要两条入口，但**内容只写一份**。

```
                     components/poi/PoiDetail.tsx   ← ★ 唯一内容实现
                     （封面 Gallery / 元信息 / 正文 / 亮点 / 来源）
                                  │
              ┌───────────────────┴───────────────────┐
              ▼                                       ▼
  PoiPreviewCard（城市页内交互用）          routes/city-poi.tsx（独立页）
  ├─ 右侧 326px 悬浮卡（预览态）             ├─ 顶栏地区按钮显示所属城市（成都）
  ├─ 打开时不改 URL（保持地图上下文）        ├─ 左侧 620px 悬浮内容面板（内部滚动）
  ├─ 底部「复制链接」→ 详情页 URL           ├─ 同款 PoiDetail
  └─ Esc / 点浮层外关闭                     └─ ★ 被预渲染成静态 HTML，供搜索引擎收录
```

- **城市页内点 marker / 卡片** → 右侧浮出预览卡，URL 不变（连续浏览多个 POI 时不打断地图上下文）
- **预览卡里点「查看详情」** → 跳 `/city/:cityId/poi/:poiId`
- **从搜索引擎或他人分享进入** → 直接落到独立详情页，内容完整可见

> 这个设计的取舍：抽屉状态不可分享，但换来了「同一份内容两种容器」的清晰边界 —— 避免同一 URL 出现两种渲染形态（那会让 SEO 与状态同步都变复杂）。想分享单个 POI，用预览卡里的复制链接按钮即可。

**独立详情页也是地图即画布**：地图铺满并定位到该 POI（保留周边点位提供空间参照），内容浮在左侧，右下角另有一张「位置与到达」浮卡。

内容顺序（**「交通」不再单独成节** —— 它与右侧「位置与到达」浮卡的信息重复，统一由浮卡承载）：

### P5 行程规划页 `/city/:cityId/plan` — 本轮新增

**产品主张**：用户自己定住宿、自己挑点位、自己排顺序，**系统只算时间**。所以这一页的主角是**时间轴**，地图是配角（提供空间校验）。

```

│ │ [← 成都]  我的行程   [第1天│第2天│第3天]      [导出] [分享]  │ │

│ │ 住宿 春熙路某酒店  [更换]  │                   │              │

│ │ │  停留 90 分 · [改]        │       │  ╱                       │

**四处关键取舍**：

| 取舍 | 说明 |
|------|------|
| **面板比城市页更宽（420px vs 348px）** | 时间轴每行要放「时间 + 名称 + 停留 + 方式 + 时长 + 距离」，348px 会挤成三行。新增 token `--panel-itinerary: 420px`，**不允许硬编码** |
| **顺序由用户定，系统只给事实与建议** | 不做自动排序。过载提示一律用「陈述 + 建议」措辞（「行程排到 22:47，可能过晚 · 建议减少 1 个点位」），**不用祈使句** |
| **降级估算的连线是直连** | ⚠️ 静态矩阵已取消（2026-10-06，改运行时算）。只有成功请求到路线规划才有真实折线；**降级为估算的段是直连**，必须标注「估算」（见 03 文档 5.1） |
| **住宿点是隐私** | 住宿点只存 `localStorage`，**不进 URL**；分享时默认脱敏为「住宿点」不带名称 |

> 移动端是同一模型：保留「地图铺满 + 连线」，行程面板换成**底部 Sheet 三档吸附**（peek 看首段 / half 看前 3–4 项 / full 完整时间轴 + 操作）。完整形态见 [08](./08-mobile-adaptation.md) 第 3·B 节。
> 行程规划器的完整产品逻辑（数据模型、通勤三级来源、时间链推导、降级）见 [09-itinerary-planner.md](./09-itinerary-planner.md)。

```

进入 /province/:adcode（省级页）
  → 该省市级面 + 各市 CountBadge（已收录市显示景点数，未收录显示"待收录"）

  → 点击未收录市 → PendingCard「内容整理中，先看看省会 / 邻近已收录市」

  → autoFit 为 true 时重新 fitBounds

hover 列表卡片 → 对应 marker 高亮（不移动地图）

## 三·B、SEO 实现清单

预渲染解决了"HTML 里有内容"，但要在搜索结果里**显示得好**，还需要下面这些：

| # | 项 | 做法 |
|---|----|------|
| S1 | 每页 `<title>` / `description` | 用 React Router 7 的 `meta()` 导出，从 loader 数据推导（见 02 文档第六节）。**全国页**（`城市旅游攻略 · 景点美食地图`）、**省级页**（`{省}旅游攻略 · {N} 个景点收录`）、**城市页**、**详情页**各自一套 |
| S2 | `canonical` | 每页指向自己的规范 URL，避免参数页重复收录 |
| S3 | Open Graph / Twitter Card | `og:title` / `og:image`（取 POI 封面）/ `og:type=article`，社交分享出大图卡片 |
| S4 | **JSON-LD 结构化数据** | 城市页 `TouristDestination`、详情页 `TouristAttraction`（含 `geo` 坐标、`address`、`image`），百度/Bing 可出富摘要；**省级页**可用 `AdministrativeArea` |
| S5 | `sitemap.xml` | 构建后脚本扫描 `dist/**/index.html` 生成，或由 `prerender()` 的路由列表直接产出。**必须涵盖 34 个省级页 + 城市页 + 全部 POI 页** |
| S6 | `robots.txt` | 放 `public/`，声明 sitemap 地址 |
| S7 | 语义化标签 | 一个 `<h1>`、层级正确的 `<h2>/<h3>`、`<nav>/<main>/<article>` |
| S8 | 图片 `alt` | Schema 已强制中文 `alt`，直接透出 |
| S9 | 内链 | 详情页加「同城同类推荐」，城市页内所有 POI 卡片都是 `<Link>`；**下钻链路本身就是天然内链**（全国 → 省 → 市层层可达） |
| S10 | 404 | Netlify 下 `_redirects` 兜底到首页，或提供独立 404 页 |

## 七、页面状态的**保持**：刷新还在，关掉重开回初始（2026-09-29）

> 用户原话：「我不管怎么弄，**打开什么东西，我只要刷新页面，就又回到了最开始打开时的样子**，
> 这个页面保持的功能得完善一下，**关掉页面重新打开，这种情况恢复最初始的版本没问题**」

最后那半句就是选型的答案 —— 它逐字对应 `sessionStorage` 的语义：

| 动作 | sessionStorage | 用户期望 |
|------|----------------|----------|
| 按 F5 / 刷新 | **保留**（同一个标签页会话） | 保留 ✓ |
| 关掉标签页再打开 | **清空** | 回到初始 ✓ |
| 新开一个标签页 | 清空（各标签页独立） | 互不干扰 ✓ |

不用 `localStorage`：它会把状态带到"下一次打开"（用户说那时该回初始），而且跨标签页共享 ——
两个标签页各看各的城市会互相改掉对方的选中。

### 存什么、不存什么（这是本节最该记住的部分）

| 存（"我打开的东西"） | 不存（"某一次交互"的中间态） |
|----------------------|------------------------------|
| 地图视野（**带 path**） | 搜索命中的那一枚 `searchPick` |
| 路线规划面板：开着 / 哪一条 / 第几天 | 「挑景点」浮层 · 「加到哪个规划」弹窗 · 重复确认 · toast |
| 各页选中的景点（**按页面身份分开**） | "在地图上取点"进行中 · 刚落下的那个取点 · 搜索框里的半截输入 |
| 城市页的筛选与排序（**按城市分开**） | |

"按页面 / 按城市分开"不是洁癖：不带身份的话，在成都选了「宽窄巷子」再换到北京，
刷新后北京页会去找一个不属于它的 id（**什么都不显示，且不报错**）。

### 三条实现纪律（每条都对应一次探针打回）

1. **唯一出口**：只有 `common/data/uiState.ts` 碰 `sessionStorage`，读失败一律退化
   （隐私模式 / 微信 WebView 下它也会抛，而它是在 store 初始化时读的 —— 抛出去就是整页白屏）。
2. **写回走 effect、盯住状态本身**：三页里写 `selectedId` 的地方有好几处（点地图 / 点清单 /
   点空白 / 收起），逐个去调 `patchPick` 一定会漏 ⇒ 收进 `useSessionState` 的 hook 里，
   一条 effect 盯住状态，所有写入点自动覆盖。
3. **「视野恢复」优先于「入口取景」**：刷新时镜头已由会话里的中心/缩放摆好，
   再跑一次 `useFitOnce` 的入口取景 = 把用户刚回到的位置又推走。判据是
   **`pathname` 是否等于页面加载时那条**（`restoredViewFor`）：
   · 刷新 / 从详情页返回本页 → 用会话里的视野；
   · 从首页点进城市页（路径变了）→ 照旧 fit 行政区。

### ★★ 一个连打回两次的坑：「当前天」的恢复

「当前天」的真源在**面板副本**（`useItineraryStore.activeDay`），而它刷新后从 `store.ts`
的初值 **1** 起步；恢复值是 `planUi.detailDay`。于是有三条互相打架的链路：

1. 面板副本的 `activeDay` 变了 → 广播给 `detailDay`（**首屏必须跳过**，否则用初值 1 覆盖恢复值）；
2. `attach()` 在数据到货的**稍后一拍**还会跑，把 `activeDay` 又重置回 1；
3. 第 2 步又会触发第 1 步，把 `detailDay` 也写成 1 —— **恢复值当场失去依据**，
   纠正在下一轮就不成立（`d > 1`），形成"点了第 2 天、刷新回第 1 天"的死循环。

⇒ 结论：**恢复值必须取自己那一份快照**（`useRef(readUiState().plan.day)`，只在首渲染求值），
不能每次去读 `planUi.detailDay`（它会被广播污染）；纠正判据用"副本停在 1、而快照值是别的天"
（用户主动切到第 1 天时不会被误纠正），用户自己切过天之后就彻底不再干预。

> 诊断脚本 `_tmp/diag_session_day.mjs`：把 `sessionStorage` 原文、`planUi.detailDay`、
> 面板副本的 `activeDay`、DOM 里 `[data-day]` **四处一起打**出来 —— 现象相同但原因可能在任意一处。
