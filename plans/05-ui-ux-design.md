# 05 · 页面结构与 UI 设计

> 视觉基调：明亮、清爽、有旅行感；信息密度中等偏上，图片是主角。
> 所有界面提示用 Tooltip 组件，禁止 HTML `title` 属性；禁止硬编码 size / shape，统一走 design token。

## 一、页面结构

### 1.0 布局模型：地图即画布（Map as Canvas）

> **这是全站唯一的布局模型，两端共用。** 早期方案里的「地图占左 60% + 列表占右 40%」分栏已废弃。

```
┌───────────────────── 屏幕视口（100% × 100%）─────────────────────┐
│                                                                  │
│                  底 层：全 屏 地 图 画 布                         │
│                （z=0，铺满，不参与文档流）                         │
│                                                                  │
│   ┌─ 浮层 A ─┐   ┌──── 浮层 B ────┐      ┌─ 浮层 C ─┐            │
│   │ 白底      │   │ 白底 + 投影     │      │          │           │
│   │ 圆角 + 投影│   │                │      │          │           │
│   └──────────┘   └────────────────┘      └──────────┘            │
│                                                                  │
│        ┌──── 浮层 D（底部条）────┐                                │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

**四条硬规则**（违反任何一条就退回分栏老路）：

1. **地图是页面本身，不是页面里的一个组件。** 屏幕容器 `position:relative`，地图层 `position:absolute; inset:0`，永远 100% × 100%。
2. **所有 UI 都是浮层**：统一 `position:absolute` + 白底 + 圆角 + 投影。没有「并排」，只有「悬浮」；没有「区块」，只有「浮层」。
3. **浮层没盖到的地方，永远露着地图。** 这意味着面板必须**定宽 / 定档位**（如左面板 348px、右卡片 326px、Sheet 三档），而不是 `flex:1` 去挤占地图。
4. **关掉任何浮层，地图不变形。** 面板是「盖」在地图上，不是「挤」地图。所以：详情面板打开时不重算地图尺寸，只让视野 `panTo` 到目标点（`map.panTo()`）。

**为什么改**：分栏模型里「地图」和「内容」在争同一块面积的解释权，结果两边都做不好 —— 地图永远只是一条窄带，而"空间关系"恰恰是地图存在的唯一理由。改成浮层后，地图拿到 100% 面积，UI 变成可以随时收起、随手拖动的注脚。

- **每个省一个计数徽标（CountBadge）**："四川 46"。数字是该省**已收录**景点数，来自构建期 `district-tree.json`，**零运行时调用**。
- **未收录的省显示"待收录"**（灰色 + 虚线描边 + 破折号 `—`），**不是 0** —— 0 表示"收录了但确实没有"，与"还没做"是两回事（见 [10](./10-map-drilldown.md) 第六节）。
- **省级填充色 = 收录密度**（四级：未收录 / 1–19 / 20–49 / 50+），让"哪里有内容"一眼可见。
- **点击省 → 下钻到 P2 省级页**。下钻是客户端路由切换，**地图实例复用、不重载**（见 [10](./10-map-drilldown.md) 第五节）。
- 左侧面板与地图双向联动（hover 行 → 省高亮；点省 → 行选中并下钻）。

> 与早期"城市选择网格"的区别：**入口从"选城市"升级为"看全国"**。用户先建立"哪里值得去、内容有多少"的整体印象，再逐级下钻，而不是一上来就在 10 个城市里二选一。

### P1·B 地域面板 —— 点省 / 市徽标，左侧开一块「这一级有什么」（2026-11-12）

> 上面 P1 的草图里画过一块「全国概览 348px 左面板」，但**那一版没实现**：
> 首页最终是「地图即画布」最纯粹的一页 —— 34 个省徽标 + 一条顶栏，没有任何清单
> （`useHomeView` 文件头专门写了"不要顺手把省份清单加回来"）。
> 代价是**点省 / 市只做一件事：放大**。屏幕上永远只有徽标和数字 ——
> 这个省收了哪几座城、是哪座城，全靠用户自己认。
>
> 现在补的不是那张常驻清单，而是**点开才出现的一张卡**：首屏仍然是一张裸地图，
> 点省徽标 → 左侧开省概览；点市徽标 → 左侧开市概览。关掉就没了。

**为什么市卡给的是「区」而不是「直接摊景点」**：用户当时的判断是"显示区可能会好一点"，
这里照办。理由与本项目其余四级下钻一致 —— 一座 69 个点位的城市平铺成 69 行扫不动，
13 个区一行一个既能认路又能看出"哪几个区有货"；而"摊景点"这件事城市页已经做得很完整
（筛选 / 排序 / 评分），不必在面板里再来一份。

#### ★★ 偏移：不写死 348 / 420，一律由 `freeRect` 现量

用户的原始要求是两句话：「省市点击现在的逻辑，还得往右偏移一点，不然可能会被挡住」
「但是还得考虑同时打开路线规划功能的情况，两种情况下的偏移不能一致」。

这两句正好否掉了"加个常量"的做法：

| 情况 | 可用区 | 落点相对屏幕中心 | 实测 `dx` |
|---|---|---|---|
| 只有左面板（348） | `[348, 1418]` | 右移 | **+172** |
| 左面板 + 右侧路线规划（420） | `[348, 998]` | **左移** | **−44** |

第三列不是笔误：右侧面板吃掉 420 之后，可用区中心从 883 退到 673，**反而跑到屏幕中线左边**。
所以"偏移量"根本不是一件事，而是**可用矩形**的函数。

实现上只有一条链路：`shell.focusPoint` 的落点本来就是「扣掉浮层之后那块空闲区的中心」
（`panTo.ts` 的 `centerOfFreeRect` + `freeRect()`，**每次调用现查 DOM**）。
于是：

1. 面板必须走 `Overlay`（它带 `data-overlay`，`freeRect` 才量得到）；
2. 顺序必须是**先开面板（render）→ 下一帧再对焦（`requestAnimationFrame`）** ——
   面板还没进 DOM 那一帧去对焦，等于按旧布局算，徽标会停在屏幕正中随后被盖住；
3. 落点的"算哪"仍然只由 `districtFocus.drillTo` 一处负责：`regionNav` 传给它一个
   「只记目标、不飞镜头」的 shell 替身，真正的 `focusPoint` 留到下一帧。

#### 四条边界

| 情况 | 表现 | 理由 |
|---|---|---|
| **直辖市 / 特别行政区** | 点北京直接摊**市卡**，没有"省概览（1 个市）"这一层 | `loadProvinceDetail` 给回的下级只有它自己一枚，摊省卡等于废话 |
| **未收录的市** | 面板里那行**可点**：开一张「XX 还没收录」的卡 + 地图飞到该市（`CITY_DRILL_ZOOM`），但**不给"查看区列表"** | 区分片是按已收录点位算的，点进去必然是空表。★ 与"地图上点它的徽标"同一个结局 —— 两条入口给同一个答案。省级页那边仍禁用：它的点击是**换页**，未收录的市没有页可换 |
| **区徽标** | 只放大 + 列表高亮，**不开卡** | 区没有"自己的介绍"可读；旧行为原样保留 |
| **移动端** | **不渲染面板**，但状态与对焦链路照跑（行为与旧版一致：只放大） | 手机屏幕放不下 348 侧栏；城市内容另有底部 Sheet 承接 |

#### ★★ 点击闭环（2026-11-14 补，用户：「点省之后再点市，不会切换到市的面板」）

面板"显示了但没换"是个**不会报错**的故障族 —— 四处独立的小毛病叠出同一个观感，
所以这里把它们并列写清（护栏 **BE** 一条一条盯着）：

| 现象 | 根因 | 修法 |
|---|---|---|
| **搜索点省市不开面板** | `useSearch` 自己算落点（`regionFocusPoints` + `focusPoint`），而"开面板"住在页面的 `useState` 里 —— 两条路各有各的落点，只有一条会开卡。镜头飞对了，面板没开 | 外壳加一条注册制信道 `PageRegionOps`：**首页登记 `region.pick`**，搜索命中地区先问 `pickPageRegion(...)`，有人接就一帧都不自己挪（`drillTo` 是唯一落点）。省级页 / 城市页没登记 ⇒ 走原路径，行为不变 |
| **城市列表里点市毫无反应** | `ProvinceList` 对未收录的市一律 `disabled` —— 陕西 10 个市里 9 个是死行。而 `CityCard` 早就写好了"还没收录"的空态卡，入口却被禁掉了 | 加 `pendingPickable`，**默认 `false`**（省级页仍禁用），只有地域面板传 `true` |
| **换卡后停在半截** | 面板是一个**不卸载的滚动容器**：省卡长（四川实测 874px）、市卡短。用户在省卡滚到中段再点市，新卡的头已经在滚动区外，屏上剩中段甚至一段空白 | `listKey`（单位 + 卡片/列表）变化时把 `.scroll` 的 `scrollTop` 归零 |
| **点未收录的市镜头一动不动** | `focusPointsFor` 的兜底对省 / 市也返回 `empty: true`，`drillTo` 就只弹一句 toast（2 秒消失） | 兜底改成 `empty: false` —— 全国 367 个市里 284 个未收录，**点了必须有位移**。★ `empty` 从此只对**区**成立：区飞过去确实只剩底图 |

顺带修掉一条搜索的老毛病：**打全称搜不到**。索引里存的是「陕西」，而用户常打「陕西省」，
`'陕西'.includes('陕西省')` 恒 false ⇒ 0 条结果。`scoreName` 原来只剥 `name` 的行政后缀，
现在**查询词也剥一次**（`bare(q)`），全称 / 简称 / 混着写落到同一档。

#### ★★ 轮廓作用域（2026-11-14 补，用户：「不管什么情况，地图轮廓都显示，点省了就只显示那个省」）

**修复前**：轮廓的判据只有**视野**。`decideReveal` 先按缩放算出该揭示到哪一级，
再拿这一级的**全部**候选过 `containsPoint` —— 首页点陕西后镜头落在 z=7（市级），
`districts('city')` 返回的是**全国 367 个市**，甘肃、四川、河南的市只要中心落进
外扩圈（区划 1 屏、面 2 屏）就一起描线。判据里**没有「用户刚点了陕西」这个维度**。

**现在**：选中谁，谁就是**作用域** —— 节点集合**先按归属裁，再按视野裁**。

| 状态 | 画什么 | 徽标 |
|---|---|---|
| 未选中（首屏 z≈4.4） | 全国 34 个省 | 34 |
| 选中省（z=7） | 省界外框 + 省内 10 个市界 | 只有本省 10 个市 |
| 选中市（z=10.5） | 市界外框 + 市内各区界 | 只有本市区县 |
| 选中区（z=12） | 只剩这一区（点位档的参考底） | 无（点位档徽标退场） |

三条口径：

1. **归属按段式前缀判**（`inScope`）：省取前 2 位、市取前 4 位、区取全 6 位。
   直辖市没有中间市层，`110101`.startsWith(`11`) 照样成立。
   ⚠️ **不能写成全等** —— 全等只对区有效，选中省 / 市会把下级全裁掉。
2. **缩回全国自动放开**：判据是「当前揭示级别比作用域单位**更深**」（用 `revealed`，
   不用可能回流的 `level`）。不放开的话，整张中国地图只剩一片有轮廓，看起来像数据丢了。
3. **省界单独画一圈**：省界在数据里就是各市外沿的拼合，与市界同粗 ⇒ 屏幕上只是一片网格，
   读不出"这是一整个省"。所以额外取一层**自身轮廓**（省优先高德、市优先 `cities/`、
   区优先 `districts-own`），画粗一档、独立几何 id。

**边界**：面板（`region`）优先于"点过的区"（`activeDistrict`）—— 面板开着市卡时点区，
作用域仍是那个**市**（用户在市的上下文里聚焦一个区）；关掉面板 = 取消选中 = 回全国。

| 件 | 位置 |
|---|---|
| 作用域判定与裁剪 | `common/map/tencent/reveal.ts`（`RevealScope` / `inScope` / `decideReveal` 第 4 参数） |
| 外框几何（签名 + 缓存 + 独立 id） | `common/map/tencent/districtScope.ts` |
| 外框样式（3px 深灰） | `common/map/tencent/districtStyles.ts` 的 `scope` 档 |
| 取数与异步时序 | `common/logic/useScopeOutline.ts` |
| 「选中 → 作用域」的翻译 | `common/logic/regionNav.ts` 的 `scopeOf` |
| 护栏 | `check_app.py` **BF**（前缀非全等 · 缩回放开 · 外框独立 id · 首页交作用域 · 依赖含作用域键） |

#### 面的三档描边（2026-11-15 补，用户：「改一版，看看效果」）

面**不按收录数量分档**（那条 2026-10-03 已删，护栏 AP 守着），但按**底图吵不吵**分三档 ——
这是唯一还剩的"看得见"维度：

| 档 | 何时（`faceLevel` / `mode`） | 描边 | 底图 |
|---|---|---|---|
| `face` | 省 / 市级面 | `rgba(110,108,102,0.7)` 2px | 浅色行政图 |
| `faceDeep` | **district 级**面 | **`rgba(66,64,59,0.95)` 2px** | **街道图**（满屏浅灰路网 + 村名） |
| `reference` | 点位 / 规划档（优先于 level 判） | `rgba(95,94,90,0.85)` 2px | 街道图 + 满屏点位 |
| **`scope`** | **选中单位自身**（与缩放、层级都无关） | **`rgba(38,36,32,0.96)` 3px** | 跟着所在档走 |

四档严格递增：`face`（浅灰 0.70）‹ `faceDeep`（深灰 0.95）‹ `scope`（近黑 0.96 + 3px）。
`scope` 是唯一**跨档**的一层 —— 它答"我选的是谁"，`face*` 答"底下怎么分"。

**为什么非要 `faceDeep`**：同视角 before/after 实拍证明几何**一直是画出来的**
（z=10.5 一屏 140 个面），0.7 alpha 的浅灰细线被街道底图吃掉 ⇒ 用户读到的是"区界没画"。
改后像素差 3.08%，而 z=4.4 / z=7.2 两档只差 0.04%（瓦片噪声）—— 就是"只动该动的那一档"。

两条纪律：
1. **换色判据跟 `faceLevel`（揭示级），不跟绝对 zoom**（2026-11-15 界面验收 P2 修正）。
   城市页 / 移动端会抬高 `base`：z=9.46 / 7.99 时 level 已是 `district`、底图同样吵，
   按 9.5 判会让「首页 → 进城市页」这条最常见路径**永远拿不到深线**。
   `faceLevel` 一变必然 `setNodes → repaint()`，反而比按 zoom 判更贴「换色点与重铺时机重合」。
   ⚠️ 点位 / 规划档的 `faceLevel` 也是 `district`，但 `mode === 'reference'` **必须先判**。
   ⚠️ 两条图层通道都要传：`useMapReveal`（首页 / 省级页下钻）与 `useCityDistrictLayer`
   （城市页自己的区图层）—— 只接前者的话 P2 等于没修。
2. **层级靠粗细，不靠颜色**：`faceDeep` 仍 2px（加粗会让 140 个面糊成网格，也会和 3px 的
   作用域外框抢权重）；`reference` 反而更浅 —— 点位档的主角是圆点，区界是背景。

**P2 实测**：城市页同视角 before/after（`_tmp/panels/p2-compare-xian.png`），
西安市域「中性深灰像素」**7935 → 16162（+104%）**；咸阳一侧仍是底图自带的浅灰线，
说明深线只落在西安市辖区、没有跑出作用域。

#### ★★ 水合稳定快照（2026-11-15 界面验收 P1）

预渲染 HTML 里路线规划面板恒为**关**；`usePlanUi` 是模块级 zustand store，
`create()` 在 JS 加载时就跑完，原实现直接读 `sessionStorage` 恢复 `panelOpen`。
用户开着面板刷新 ⇒ 客户端首帧多渲染一个 `<MobileRoutePlanPanel>` ⇒ React 判定
hydration mismatch、**丢弃整棵服务端 DOM 重渲染**；重渲染 `<head>` 又撞上
`loader.ts` 动态插入的腾讯 SDK `<script>`，刷出 console.error，该次 LCP 2748ms。

口径与 `useViewport` 一致：**服务端 / 水合首帧用稳定快照，水合后立刻同步真值**。

| 层次 | 做法 |
|---|---|
| store 初值 | `panelOpen: false`、`detailDay: 1`（与预渲染一致），**不读** sessionStorage |
| 恢复入口 | `restorePanelUi()` 一次 `setState` 接回两个字段，挂 `routes/map-shell.tsx` 的挂载 effect |
| 不用 `useLayoutEffect` | 预渲染在 Node 里跑，layout effect 在服务端会警告；`useEffect` 晚一帧远优于整树重渲染 |

A/B/C 三组对照：面板关 `0/0` · **开着→导航 `0/0`**（修前 `1/1`）· 再关 `0/0`；
且导航后 `panelOpen` 仍为 `true` —— 刷新保持状态的功能没丢。护栏 **BG** 守着。

#### 刻意不做

- **不做常驻省清单**：首页首屏必须是裸地图（P1 的设计意图，也是 `useHomeView` 的纪律）。
- **不在面板里摊景点**：见上面「为什么给区」。
- **不做面板宽度跟内容变**：`--panel-left` 是全局 token，四种卡共用；变宽会牵动 `freeRect`。

| # | 原则 | 为什么 |

#### 2026-11-14 与景点详情对齐（用户原话：「介绍整体上和景点介绍统一一下」）

统一前是**两套阅读语言**，谁都不报错，只有来回翻的用户能感到别扭：

| | 景点详情（基准） | 城市介绍（统一前） | 现在 |
|---|---|---|---|
| 图集 | 底部缩略条，当前那张套 `ring-2` | **点封面图翻下一张** + 「1/3」角标 | 缩略条（同一份 `GalleryStrip`） |
| 正文 | `15.5px / 1.75`，桌面 `14px` | `12.5px` | `Prose`（同一份） |
| 分节 | `H2`「亮点 / 实用信息 / 小提示」 | 无 | `H2`「实用信息」（同一份） |
| 事实 | `dl` 标签列 `84px`、`13px` | 标签列 `auto`、`11.5px` | 同 84px / 13px |
| 长文 | 全展开 | `line-clamp` + 「展开城市介绍」 | **全展开** |

**为什么以景点详情为基准**：它是本站内容最完整的一屏（图集 + 正文 + 点评 + 亮点 +
实用信息 + 提示 + 溯源 + 位置交通），其余各页都是它的子集，往上靠才不会走形。

**为什么把折叠去掉**：折叠的含义是"这段你可以不读"，可一座城只有这一份介绍；
景点简介从不折，城市却要用户多点一次才读完，那就是两套语言。
代价是城市页首屏会被介绍占掉大半 —— 接受：这一页的**第一件事**就是"这是座什么城"，
点位列表往下滚一屏（介绍在滚动区顶部，本来就不钉住）。

**为什么点封面翻页是错的**（用户最先指出的那条）：
① 图上没有任何可点的迹象 ⇒ 另外两张等于白存；
② 「1/3」只说了共三张，看不出另外两张是什么；
③ 封面套在 `<button>` 里，以后想加"点开大图"就没地方挂。
缩略条一次解决三件事，而且与景点详情长得一样。

**唯一出处**（都在这两个文件里，别处不许再写一份）：

| 件 | 位置 |
|---|---|
| 正文排版（`Prose` / `H2`） | `web/app/common/ui/Section.tsx` |
| 图集 + 缩略条（`HeroGallery` / `GalleryStrip`） | `web/app/common/ui/HeroGallery.tsx` |
| 护栏 | `check_app.py` **BD**（排版基座不许绕开 · 缩略条唯一实现 · 城市介绍不许折叠/点图翻页） |

#### 三个刻意不做的事

- **不做自动轮播**：3 张封面自动播 → 用户必然错过 2 张，而且看不出"还能翻"。
- **不在列表行放缩略图**：行高 34px 塞图 ⇒ 每条都变成卡片，几十条扫不动（列表的活是"扫一遍有什么"）。
- **不做城市卡片瀑布流**：与「地图即画布」直接冲突（P3 的整块地图会被切走）。

### P1·C 省级介绍与封面 —— 省也得是「可读对象」（2026-11-14）

> 用户问「省的介绍和图片不抓吗」。查下来的答案不是"抓了没显示"，而是
> **省级在 `data/` 里只有区划与边界**（`_generated/provinces/*.geo.json`），
> 一个字、一张图都没有。所以省卡此前只能把"下辖 10 个地级市、已收录 1 座、
> 共 69 个点位、其余 9 个还在采集"拼成一段话 —— 那是**收录进度**，
> 不是"这个省是什么样"。市卡有封面有简介，省卡只有进度，两级的"可读性"差一整级。

#### 数据形状

`data/provinces/index.json`（一份，约 12KB；键 = 6 位省级 adcode）：

```json
{
  "updatedAt": "2026-11-14",
  "provinces": {
    "610000": {
      "intro": "陕北、关中、陕南三块。关中是主体：西安的明城墙、兵马俑…",
      "heroImages": [ /* 与 City.heroImages 同一份 ImageItem 形状 */ ]
    }
  }
}
```

* **`intro` 是采编正文**（真实人文地理，不编数据），34 个省级单位各一段，
  由人写进 `data/provinces/index.json`；与城市 `intro` 的关系是"省级视角"，不是城市简介的拼接。
* **`heroImages` 允许为空**（`max_length: 3`，没有 `min_length`）——
  与 `City.heroImages` 的 `min_length: 1` 刻意不同：城市封面是"点进这座城市唯一的视觉锚点"，
  省卡没有它也成立（退回只显示简介 + 收录情况）。
* 契约两侧：`schema.py` 的 `ProvinceContent` / `ProvinceIndex` ↔ `schema.ts` 同名。

#### 为什么省封面不能用省名搜图

| 查询词 | Commons 结果 |
|---|---|
| 「陕西 城市风光」/「Shaanxi」 | 大量**行政区划图、空白轮廓图、路牌**，一张都不能用 |
| 「兵马俑」/「华山」/「西安城墙」 | 有真实照片 + 人工分类 ⇒ 这才是"这个省的门面" |

所以 `tools/province_cover.py` 的地标来源是**该省所有已收录城市的点位，按 `popularity` 降序取前 6**。
省级**不再**做 bbox / 50km 过滤（城市封面必须排掉"华山属渭南"，但华山**属陕西**，当陕西省封面是对的）。

其余口径与城市封面完全一致：**只收 Wikimedia** → 逐张看图 → `alt` 必须中文 ≥8 字、最多 3 张 →
判 ok 不足 1 张**不动旧值**。账本 `data/_generated/province-covers.json`。
看图为省时间做了**合表**：`sheet all --per 6` 会把多个省拼进一张图，每省**每个地标各一张**
（不是"最热那个地标 ×6"，否则整行都是同一处，等于没得挑）。

#### 省卡长什么样（与市卡、景点详情同一套排版）

```
┌ 省概览 ──────────────────────────┐
│ 陕西省                      省概览 ×│
│ [省封面（有图才出现）+ 缩略条]     │
│ 陕北、关中、陕南三块。关中是主体…  │ ← Prose：15.5 / 桌面 14px
│ 收录情况                          │ ← H2
│ 陕西下辖 10 个地级市，已收录 1 座… │
│ ── 已收录的城市 ──────────────    │
│ 西安  十三朝古都，一眼千年   69 个 ›│
│ 其余 9 个市还在采集…               │
│ ─────────────────────────────    │
│ 查看城市列表                    › │
└──────────────────────────────────┘
```

★ 「收录情况」用 `H2` 而不用 `SectionLabel`：它和「实用信息」是同一级信息
（一段可读的结论），而「已收录的城市」是清单的标签 —— 两者不该长一个样。

#### 刻意不做

- **不写"省级 facts"**（最佳季节 / 建议天数 / 气候）：一个省跨几个气候带，
  写一句话就是错的；市级那四项能成立是因为它真的只描述一座城。
  没数据就不渲染那一节，不拿泛泛的描述凑数。
- **不给省排名 / 打分**：无权威来源的评分是伪数据（与"不引入 rating"同一条）。
- **不在省卡摊景点**：省这一级要回答"这个省有什么，我能去哪几座城"，
  摊景点是市级与城市页的活（P3·B 那条同源）。

### P4 POI 详情（双轨：城市页抽屉 + 独立详情页）

**SEO 带来一个连锁变更**：抽屉是纯前端交互态，搜索引擎抓不到、也无法单独分享。所以详情需要两条入口，但**内容只写一份**。

```
                     components/poi/PoiDetail.tsx   ← ★ 唯一内容实现
                     （封面 Gallery / 元信息 / 正文 / 亮点 / 来源）
                                  │
              ┌───────────────────┴───────────────────┐
              ▼                                       ▼
  PoiPreviewCard（城市页内交互用）          routes/city-poi.tsx（独立页）
  ├─ 右侧 326px 悬浮卡（预览态）             ├─ 顶栏地区按钮显示所属城市（成都）
  ├─ 打开时不改 URL（保持地图上下文）        ├─ 左侧 620px 悬浮内容面板（内部滚动）
  ├─ 底部「复制链接」→ 详情页 URL           ├─ 同款 PoiDetail
  └─ Esc / 点浮层外关闭                     └─ ★ 被预渲染成静态 HTML，供搜索引擎收录
```

- **城市页内点 marker / 卡片** → 右侧浮出预览卡，URL 不变（连续浏览多个 POI 时不打断地图上下文）
- **预览卡里点「查看详情」** → 跳 `/city/:cityId/poi/:poiId`
- **从搜索引擎或他人分享进入** → 直接落到独立详情页，内容完整可见

> 这个设计的取舍：抽屉状态不可分享，但换来了「同一份内容两种容器」的清晰边界 —— 避免同一 URL 出现两种渲染形态（那会让 SEO 与状态同步都变复杂）。想分享单个 POI，用预览卡里的复制链接按钮即可。

**独立详情页也是地图即画布**：地图铺满并定位到该 POI（保留周边点位提供空间参照），内容浮在左侧，右下角另有一张「位置与到达」浮卡。

**四处关键取舍**：

| 取舍 | 说明 |
|------|------|
| **面板比城市页更宽（420px vs 348px）** | 时间轴每行要放「时间 + 名称 + 停留 + 方式 + 时长 + 距离」，348px 会挤成三行。新增 token `--panel-itinerary: 420px`，**不允许硬编码** |

## 三、交互流程

```
进入 /（全国页）
  → 预渲染 HTML 已就位（各省景点数来自 district-tree.json）
  → hydrate → 地图铺满 → 画 34 个省级面 + CountBadge → fitBounds(全国)
  → 未收录省渲染"待收录"灰显（点击弹引导，不下钻）
  → 点击某省级面 / 面板行 → 客户端路由切到 /province/:adcode
      地图实例**复用不重载**，只换图层（省面 → 市面）与视野（fitBounds 到该省）

进入 /province/:adcode（省级页）
  → 该省市级面 + 各市 CountBadge（已收录市显示景点数，未收录显示"待收录"）
  → 点击已收录市 → /city/:cityId（进入下面「进入城市页」流程）
  → 点击未收录市 → PendingCard「内容整理中，先看看省会 / 邻近已收录市」
  → 顶栏地区按钮写着「四川」，点开可跳到全国 / 任意省 / 任意市（不必逐级退回）

进入城市页
  → 预渲染 HTML 已就位（文案立即可见，无骨架屏）
  → hydrate → 地图铺满视口 → 初始化 → fitBounds(allPois, padding)   ← padding 来自浮层实测
  → 浮层就位：顶栏 / 左面板 / 控件组
  → 默认「全部」大类 + 默认底图（矢量图 · 详细；**不随缩放自动切换**，见 03 文档 2.1.1）

点击分类 Tab / 细类图例
  → 过滤 visiblePois → 图层 clear + add（marker 颜色按 subtype 渲染）
  → autoFit 为 true 时重新 fitBounds

hover 列表卡片 → 对应 marker 高亮（不移动地图）
点击 列表卡片 / marker
  → 双向选中 → panTo 定位 → 右侧浮出 PoiPreviewCard（URL 不变）
  → 再点「查看详情」→ 跳 PoiDetail 独立页
关闭预览卡 → 保留选中态，便于继续看下一个；地图不重算尺寸

在底图菜单里换类型 / 切档位 / 动开关 → map.setBaseMap(由状态派生的 config) → 同步 localStorage
放大到街区级 → **什么都不发生**（底图完全由用户的选择决定，见 03 文档 2.1.1）
key 缺失 / SDK 失败 → 浮出引导卡片（含"使用我自己的 Key"入口），左面板列表 + 详情**照常完全可用**

搜索输入（防抖 300ms）→ 名字/tags/描述匹配 → 空结果给引导文案
手动拖动地图 → autoFit=false → 显示"回到全览"按钮
移动端：地图铺满视口，**单指直接拖地图**（app-shell 下页面本身不滚，无手势冲突）
        → 点 marker 不弹气泡：Sheet 升到 half 档 + 卡片高亮并滚入视野
        → Sheet 三档吸附（peek / half / full），到顶下拉可降档（见 08 文档第三节）

── 行程规划页（P5，见 09 文档）────────────────────────────────
进入 /city/:cityId/plan
  → 空壳已预渲染（含说明与引导）；行程数据从 localStorage 读取填充
  → 无行程 → 引导「先选一个住宿点」（StayPicker 打开）
  → 有行程 → 渲染时间轴 + 地图连线 + 视野框住当天点位

设定住宿点（StayPicker）
  → 三路：从 POI 里选 / 搜索地址（走地理编码，1 次调用）/ 地图上点选（拖拽确认）
  → 支持多住宿段：加第二个酒店时要求指定「从第几天到第几天」

添加点位 → 复用城市页的 PoiPickerSheet（**不重新实现一套选择器**）
  → 选中后追加到当天末尾，时间链重算（★ 矩阵已取消：缓存命中 → 同步重算；未命中 → 显示"计算中"，异步补算后再重算）

拖拽排序
  → 同一天内：直接生效，连线与时间链实时重算（每帧 ≤ 16ms）
  → 拖到另一天：若目标天的 stayId 不同 → 二次确认「第 3 天住的是另一个酒店，仍要移过去吗？」
  → 移动端：**长按 300ms 激活拖拽态**，避免与 Sheet 下拉手势打架

修改停留时长 / 切换某段交通方式
  → 时长：时间链重算
  → 方式：走**两级解析**（缓存 → 实时）。★ 2026-10-06 起矩阵取消，所有方式在缓存未命中时都会触发实时调用，显示 loading 态
  → 方式切换（六种：驾车 / 打车 / 公交 / 地铁 / 骑行 / 步行）**各给多条备选路线**（驾车走 `get_mp=1` 拿最多 3 条 + `get_speed=1` 显示路况，点开某段才懒加载）
  → 「不适用」的方式灰掉并给出可用方式提示（如「步行不适用 12.3 km · 建议驾车 22 分」）

时间链完成 → 过载检查（结束晚于 22:00 / 在途占比过高 / 单段超 60 分）
  → 以「陈述事实 + 建议」措辞提示，**不用祈使句**（顺序的决定权在用户）

导出 / 分享 → 导出 JSON 文件 / 生成分享链接（LZ-string 压进 URL hash，纯前端可解）
  → ⚠️ 分享时住宿点**默认脱敏**（只显示「住宿点」不带名称）
```

> ⚠️ **地图挂了不影响行程**：时间链计算走 Web 服务 JSONP，**不依赖地图实例**（⚠️ 矩阵已于 2026-10-06 取消，改为运行时算）。实现时必须守住这个边界 —— 不要把通勤计算写成需要 `map` 参数的代码。城市页与行程页共用 `MapFallback` 降级卡片。

## 三·B、SEO 实现清单

预渲染解决了"HTML 里有内容"，但要在搜索结果里**显示得好**，还需要下面这些：

| # | 项 | 做法 |
|---|----|------|
| S1 | 每页 `<title>` / `description` | 用 React Router 7 的 `meta()` 导出，从 loader 数据推导（见 02 文档第六节）。**全国页**（`城市旅游攻略 · 景点美食地图`）、**省级页**（`{省}旅游攻略 · {N} 个景点收录`）、**城市页**、**详情页**各自一套 |
| S2 | `canonical` | 每页指向自己的规范 URL，避免参数页重复收录 |
| S3 | Open Graph / Twitter Card | `og:title` / `og:image`（取 POI 封面）/ `og:type=article`，社交分享出大图卡片 |
| S4 | **JSON-LD 结构化数据** | 城市页 `TouristDestination`、详情页 `TouristAttraction`（含 `geo` 坐标、`address`、`image`），百度/Bing 可出富摘要；**省级页**可用 `AdministrativeArea` |
| S5 | `sitemap.xml` | 构建后脚本扫描 `dist/**/index.html` 生成，或由 `prerender()` 的路由列表直接产出。**必须涵盖 34 个省级页 + 城市页 + 全部 POI 页** |
| S6 | `robots.txt` | 放 `public/`，声明 sitemap 地址 |
| S7 | 语义化标签 | 一个 `<h1>`、层级正确的 `<h2>/<h3>`、`<nav>/<main>/<article>` |
| S8 | 图片 `alt` | Schema 已强制中文 `alt`，直接透出 |
| S9 | 内链 | 详情页加「同城同类推荐」，城市页内所有 POI 卡片都是 `<Link>`；**下钻链路本身就是天然内链**（全国 → 省 → 市层层可达） |
| S10 | 404 | Netlify 下 `_redirects` 兜底到首页，或提供独立 404 页 |

> ⚠️ **验收必须用 `npm run build && npm run preview`**。`npm run dev` 是 CSR，`查看源代码` 里只有空壳 —— 拿它验 SEO 会得出错误结论。最快自检：
> ```bash
> npm run build && grep -o '<title>[^<]*</title>' dist/city/chengdu/index.html
> grep -c '武侯祠' dist/city/chengdu/poi/wuhou-shrine/index.html

| 档 | 宽度 | 浮层布局要点（底层永远是全屏地图） |
|----|------|---------|

### 无障碍与细节
- 图片必须有 `alt`；图标按钮必须有 `aria-label`。
- 键盘：Tab 可遍历卡片，Enter 打开详情，Esc 关闭当前浮层（预览卡 / Sheet）。
- 空态：无结果 / 地图加载失败（提示 + 重试 + 静态降级列表）/ **未收录的省或市（"待收录"灰显 + 引导卡，不是空白）**。
- **适游群体标签**必须能被读屏读出（不是纯装饰图标）；**♿ 无障碍友好**用图标 + `aria-label="无障碍友好"`，且**只在 `accessible=true` 时渲染**（默认不显示，避免用"没有标识"暗示"不友好"）。
- 骨架屏：城市 JSON 加载、图片加载各一套；**下钻换层时保留上一层的面与徽标**，不做整屏骨架（避免闪烁）。

## 七、页面状态的**保持**：刷新还在，关掉重开回初始（2026-09-29）

> 用户原话：「我不管怎么弄，**打开什么东西，我只要刷新页面，就又回到了最开始打开时的样子**，
> 这个页面保持的功能得完善一下，**关掉页面重新打开，这种情况恢复最初始的版本没问题**」

最后那半句就是选型的答案 —— 它逐字对应 `sessionStorage` 的语义：

| 动作 | sessionStorage | 用户期望 |
|------|----------------|----------|
| 按 F5 / 刷新 | **保留**（同一个标签页会话） | 保留 ✓ |
| 关掉标签页再打开 | **清空** | 回到初始 ✓ |
| 新开一个标签页 | 清空（各标签页独立） | 互不干扰 ✓ |

不用 `localStorage`：它会把状态带到"下一次打开"（用户说那时该回初始），而且跨标签页共享 ——
两个标签页各看各的城市会互相改掉对方的选中。

### 存什么、不存什么（这是本节最该记住的部分）

| 存（"我打开的东西"） | 不存（"某一次交互"的中间态） |
|----------------------|------------------------------|
| 地图视野（**带 path**） | 搜索命中的那一枚 `searchPick` |
| 路线规划面板：开着 / 哪一条 / 第几天 | 「挑景点」浮层 · 「加到哪个规划」弹窗 · 重复确认 · toast |
| 各页选中的景点（**按页面身份分开**） | "在地图上取点"进行中 · 刚落下的那个取点 · 搜索框里的半截输入 |
| 城市页的筛选与排序（**按城市分开**） | |

"按页面 / 按城市分开"不是洁癖：不带身份的话，在成都选了「宽窄巷子」再换到北京，
刷新后北京页会去找一个不属于它的 id（**什么都不显示，且不报错**）。

### 三条实现纪律（每条都对应一次探针打回）

1. **唯一出口**：只有 `common/data/uiState.ts` 碰 `sessionStorage`，读失败一律退化
   （隐私模式 / 微信 WebView 下它也会抛，而它是在 store 初始化时读的 —— 抛出去就是整页白屏）。
2. **写回走 effect、盯住状态本身**：三页里写 `selectedId` 的地方有好几处（点地图 / 点清单 /
   点空白 / 收起），逐个去调 `patchPick` 一定会漏 ⇒ 收进 `useSessionState` 的 hook 里，
   一条 effect 盯住状态，所有写入点自动覆盖。
3. **「视野恢复」优先于「入口取景」**：刷新时镜头已由会话里的中心/缩放摆好，
   再跑一次 `useFitOnce` 的入口取景 = 把用户刚回到的位置又推走。判据是
   **`pathname` 是否等于页面加载时那条**（`restoredViewFor`）：
   · 刷新 / 从详情页返回本页 → 用会话里的视野；
   · 从首页点进城市页（路径变了）→ 照旧 fit 行政区。

### ★★ 一个连打回两次的坑：「当前天」的恢复

「当前天」的真源在**面板副本**（`useItineraryStore.activeDay`），而它刷新后从 `store.ts`
的初值 **1** 起步；恢复值是 `planUi.detailDay`。于是有三条互相打架的链路：

1. 面板副本的 `activeDay` 变了 → 广播给 `detailDay`（**首屏必须跳过**，否则用初值 1 覆盖恢复值）；
2. `attach()` 在数据到货的**稍后一拍**还会跑，把 `activeDay` 又重置回 1；
3. 第 2 步又会触发第 1 步，把 `detailDay` 也写成 1 —— **恢复值当场失去依据**，
   纠正在下一轮就不成立（`d > 1`），形成"点了第 2 天、刷新回第 1 天"的死循环。

⇒ 结论：**恢复值必须取自己那一份快照**（`useRef(readUiState().plan.day)`，只在首渲染求值），
不能每次去读 `planUi.detailDay`（它会被广播污染）；纠正判据用"副本停在 1、而快照值是别的天"
（用户主动切到第 1 天时不会被误纠正），用户自己切过天之后就彻底不再干预。

> 诊断脚本 `_tmp/diag_session_day.mjs`：把 `sessionStorage` 原文、`planUi.detailDay`、
> 面板副本的 `activeDay`、DOM 里 `[data-day]` **四处一起打**出来 —— 现象相同但原因可能在任意一处。
